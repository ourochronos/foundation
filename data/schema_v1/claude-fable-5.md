No tools needed — this is a judgment call. Positions below.

---

**1. The field we will regret: `object.marker: "SOME"|"NONE"` — and it will take `polarity` down with it.**
"Bourdain had no children" has two legal encodings: `polarity:"-"` + `marker:SOME`, or `polarity:"+"` + `marker:NONE`. Two encodings of the same sentence in a gold set is not a low-IAA problem, it's a training-signal contamination problem: the model is penalised for producing a correct answer. Given that negation is *the* motivating finding (25.1% philosophy), corrupting the polarity channel with a redundant quantifier enum is the single most expensive latent bug here. Delete `marker`, or define polarity as sentence-level cue presence and markers as quantification only, with a written decision procedure — before annotation starts.

Cost-per-value ranking, worst first: `under_assumption` (free text — see below), `marker`, `attribution.mode` (4-way; asserts/infers agreement will be poor, FactBank-style), `link_confidence` (subjective, redundant — the closure decides anyway), `evidence_span` (char offsets: annotators disagree on boundaries and 1.5–3B models are demonstrably bad at emitting character offsets; emit the quoted string, align offsets mechanically post-hoc), `flags` (cheap, fine as diagnostic). Best value: polarity, s/p/o, entities, `attribution.holder`.

**2. What's missing that will invalidate the annotation: claim-to-claim relations.** Your own measurement says discourse *cites and disputes, it does not repeat* — and the schema has no way to say "claim c2 disputes c1". For four of your five corpora, the signal you measured as existing is inexpressible in the schema you're about to annotate against. Adding a `relations: [{type: disputes|cites|supports, target}]` block later means re-reading every document. Second: **nested attribution**. "The Times reported that Smith denied X" needs a chain; a single holder+mode flattens it, and reports-of-denials are routine in reportage — your only corroboration domain. Make `attribution` a list now even if you only annotate depth-1. Third, note the trap in "absent qualifier = unrestricted": under that semantics *any* scope field added later retroactively falsifies old annotations (they'd claim unrestricted). Scope fields are keep-now-or-never; everything else can be additive.

**3. Attribution vs claimant: annotate the claimant, derive the qualifier. Never annotate both.** The annotation-time test is syntactic and deterministic: is there a reporting/stance frame in the text ("holds that", "argues", "according to")? Then `holder=Keynesians`, and the document author's act is `reports`. `under_assumption` is reserved for cases where the *source itself* conditionalises ("under Keynesian assumptions, X"). exp72's result survives because the closure can mechanically project claim-acts-by-schools into assumption scopes at query time — that mapping is code, not annotation. Letting annotators choose between two semantically-overlapping encodings is exactly the marker/polarity bug again. One free-text warning: `under_assumption` as a string is a **fourth open vocabulary**, and your own experiment showed one open vocabulary out of three kills corroboration (316→510 concepts). Two annotators will never write the same assumption string; scope overlap will silently never fire cross-source. It must be an entity reference or a closed frame inventory, or it's decorative.

**4. Bundle-and-decompose is sound.** The fields are individually meaningful because each is supervised against independent gold; joint training doesn't blur semantics, it correlates *errors* (wrong `e1` poisons every claim referencing it). That's a metric problem, not a design problem — solve it with alignment-forgiving scoring (score claims under best entity-id remapping). The real risks are mundane: document-unit extraction vs a small model's effective context, and offset emission (fixed by quoting spans). Do not retreat to a pipeline over this; Covalence already paid for that lesson.

**5. Steelman, and it's strong: "fine-tuning is the only option that can learn polarity" is unproven — it's the only option among the ones you tested.** The REBEL-vs-Gemma comparison is confounded by your own admission (first-draft prompt), and a well-instructed larger model with schema-constrained JSON decoding expresses polarity, attribution and scope *natively* — those are instruction-following tasks, not learned-representation tasks. Settling evidence: take 50–100 gold documents, run an iterated few-shot prompt with constrained decoding on a strong open model, score per-field against the same gold. If polarity F1 lands within ~5 points of the fine-tune, the fine-tune buys only inference cost. Crucially, **you need the annotated gold either way — for evaluation**. So the sequencing answer is: the annotation is not contingent on the fine-tune decision; the schema is the sunk cost, the model is not. Annotate first, benchmark both, decide second. The per-stage off-the-shelf pipeline steelman, by contrast, is dead — coref is context-dependent and no shelf part emits polarity; don't revisit it.

**6. Smallest schema that works:**
- **Keep:** entities (surface, type), claims (s/p/o incl. literals), `polarity`, `attribution` as a *list* of {holder, mode} with mode collapsed to `author|reported` (the 4-way split can be refined later by relabelling a 2-way field — that's additive; the reverse isn't), `valid_time`, `under_assumption` as closed reference, evidence as quoted text, and a minimal `disputes/supports` relation.
- **Cut:** `marker`, `link_proposal`/`link_confidence` (linking is a separate, cheaper, *additive* pass per entity — it never invalidates claims), `flags` as gold (keep as annotator scratch), `valid_place` only if you accept it's gone forever (I would; nothing in your measurements needed it), char offsets.

What breaks: nothing measured. Cutting attribution or polarity would break everything measured; cutting linking breaks nothing because the closure owns identity anyway — which the design already concedes.

**Bottom line:** don't abandon. Fix the polarity/marker collision, close the `under_assumption` vocabulary, add depth-capable attribution and claim-relations, cut linking from the annotation target — *then* spend the budget. And run the prompt-engineering benchmark before training, not after; the gold set you're building is exactly the instrument that settles it.
